## Readiness and operator boundaries

- **Local/staging/owner/production are separate gates.** Fresh local regression: 123 files, 782 tests passed; typecheck, lint, format, build and secret scan passed (`work/overnight-audit/resumed-final-gates.json`).
- **Operator boundary:** `scripts/outbox-operations.ts list [--limit N]` and `inspect <outbox_id>` expose read-only metadata using explicitly supplied `DATABASE_URL`, without loading `.env`. No generic replay/recovery command exists. Operator UI, audit browsing/export, owner acceptance and production recovery remain separate gaps; current authorization spec remains sole-root FR021/FR022/SR306.
- **External effects remain at-least-once.** Telegram/supplier/payment providers can retry or succeed before local ack; the code relies on the business unique keys above for exactly-once domain effects.
- **No production-ready assertion:** live SePay canary, real supplier canary/SLO, production backup/PITR/RPO/RTO, vault recovery, and authorized SKU/supplier sign-off are not established here.
