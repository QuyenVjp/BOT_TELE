## Readiness boundaries

- **Local**: source-level and disposable PostgreSQL evidence exists for most business invariants; this is the strongest current readiness lane.
- **Staging**: only limited health/webhook/Mini App synthetic evidence is recorded; no fresh owner-operated full commerce run was produced in this assignment. Main reported queryplan 16 tests pass, 132 security/recovery pass, and prior full regression 768 pass; this doc does not upgrade staging readiness from those reports.
- **Owner/operator**: sole-root admin and high-risk confirmation primitives exist (FR021/FR022/SR306), but full operator UI, owner approval/acceptance flows, audit/queue UI, and refund/replacement runbooks are still incomplete.
- **Production**: no capability above is production-ready. Missing gates include live SePay canary, real supplier canary/SLO, Telegram bridge acceptance, production backup/PITR/RPO/RTO, external vault recovery, owner approval workflow acceptance, step-up policy, dead-letter/audit operations UI, and authorized SKU/supplier sign-off.

## Resumed local verification

- Optional stock announcements now enter the existing owner preview/confirm/cancel workflow from supported in-stock inventory variants. General announcements require shop-update consent; automatic product-specific restock subscriptions are unchanged.
- Numeric `admin:<option>:<ULID>` callbacks now use actor-bound tokens. Textual admin navigation retains existing server-side root/private authorization.
- Read-only dead-letter CLI: `scripts/outbox-operations.ts list [--limit N]` and `inspect <outbox_id>`. No generic replay, recovery mutation or operator Telegram UI is claimed.
- Fresh local checks: 123 test files, 782 tests passed; typecheck, lint, format, build and secret scan passed. See `work/overnight-audit/resumed-final-gates.json` and `resumed-runtime-current.json` for scope and metrics. These supersede older test totals above, not external readiness boundaries.

## Immediate P0

- Keep the retail customer surface narrow: catalog/search → buy now → VietQR/SePay → delivery; do not add production money or supplier controls to customer UI.
- Complete owner-operated acceptance for product/variant/type, inventory import, purchase/payment, fulfillment, replacement/refund, and supplier mapping before calling any lane ready beyond local.
- Complete operator/audit/dead-letter surfaces before unattended live money, refund, broadcast, supplier, or replacement workflows; keep root-only authorization separate from owner approval.
- Treat backup/restore evidence as synthetic local proof only until production-sized restore, PITR, RPO/RTO, encrypted retention, and vault recovery are proven.
